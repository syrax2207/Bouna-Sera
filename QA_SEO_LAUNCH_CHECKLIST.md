# 8. QA, SEO & Launch Checklist

## 8.1 Functional QA

- [ ] Logo returns to top/home.
- [ ] All navigation anchors work.
- [ ] Mobile menu opens and closes.
- [ ] Escape closes dialogs/drawer where expected.
- [ ] Focus is managed correctly.
- [ ] Menu categories work.
- [ ] Menu search works.
- [ ] Combined filters work.
- [ ] Empty state appears correctly.
- [ ] Dish dialog opens and closes.
- [ ] Gallery lightbox opens.
- [ ] Next/previous works.
- [ ] Keyboard navigation works.
- [ ] Touch behavior checked.
- [ ] Phone link uses verified number.
- [ ] WhatsApp link uses verified number.
- [ ] Map link points to correct business.
- [ ] Social links are official.
- [ ] No dead buttons or fake form submissions.

## 8.2 Responsive QA

Test at representative widths:
- [ ] Small mobile: 320–375px.
- [ ] Standard mobile: 390–430px.
- [ ] Tablet: 768–1024px.
- [ ] Laptop: 1280–1440px.
- [ ] Large desktop: 1600px+.

Check:
- [ ] No horizontal overflow.
- [ ] Headings wrap cleanly.
- [ ] Buttons remain tappable.
- [ ] Images crop appropriately.
- [ ] Navigation remains usable.
- [ ] Gallery adapts.
- [ ] Fixed mobile actions do not obscure content.

## 8.3 Accessibility

- [ ] Semantic landmarks.
- [ ] Logical heading hierarchy.
- [ ] Descriptive link/button labels.
- [ ] Image alt text.
- [ ] Keyboard navigation.
- [ ] Visible focus.
- [ ] Dialog focus handling.
- [ ] Sufficient contrast.
- [ ] Reduced-motion support.
- [ ] Form labels and errors, if forms exist.
- [ ] No color-only meaning.

## 8.4 Performance

- [ ] Optimize hero image.
- [ ] Lazy-load below-fold images.
- [ ] Set image width/height or aspect ratio.
- [ ] Avoid oversized images.
- [ ] Avoid unnecessary font weights.
- [ ] Avoid continuous expensive animations.
- [ ] Check layout shifts.
- [ ] Check console and network failures.
- [ ] Run production build.

Use Lighthouse or equivalent when available. Treat scores as diagnostic, not as a substitute for real-device testing.

## 8.5 SEO

- [ ] Unique page title.
- [ ] Useful meta description.
- [ ] Canonical URL after domain selection.
- [ ] Open Graph title/description/image.
- [ ] Correct heading structure.
- [ ] Descriptive image alt text.
- [ ] LocalBusiness structured data with verified facts only.
- [ ] Sitemap if appropriate.
- [ ] Robots.txt if appropriate.
- [ ] No placeholder domain in canonical metadata.
- [ ] No false keyword stuffing.
- [ ] Business name/address/phone consistent with owner-approved details.

## 8.6 Production and owner handover

Before public launch:
- Obtain written owner approval for copy, images, menu, prices, contact details and brand use.
- Agree who owns the domain, hosting, source code and maintenance.
- Replace all placeholders.
- Remove development/debug content.
- Configure HTTPS and domain.
- Configure analytics only with owner approval and appropriate privacy disclosure.
- Test forms and integrations.
- Provide owner with a clear handover and maintenance scope.

## 8.7 Honest presentation

When showing the prototype to the prospect:
- Label it as an independent concept/demo.
- Do not imply affiliation or authorization.
- Do not publish it under a confusing official-looking domain.
- Do not use private or copyrighted imagery without permission.
- Do not claim guaranteed SEO ranking, traffic or revenue.
